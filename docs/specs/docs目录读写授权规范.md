# AI 执行者 docs 目录读写授权规范

适用范围：AI 对 `docs/` 的搜索、浏览、列举、读取、新建、修改和迁移，以及功能工作结束时的文档收敛检查。

本文规定各目录在什么情况下可以读取或写入，以及各类信息的权威位置。即使文件未被 `.ignore` 排除，也要遵守本文的授权要求。

`.ignore` 排除的内容如何访问，以及文档、代码等不同产物如何获得修改授权，仍遵守[项目协作规则](../../AGENTS.md)。

## 1. 默认读写权限

| 目录 | 定位 | 默认读取 | 写入条件 |
| --- | --- | --- | --- |
| `docs/specs/` | 正式项目规范及配套模板 | 按任务需要读取适用规范 | 已获授权的规范维护 |
| `docs/features/` | 功能规格、当前设计及工作记录 | 按任务需要读取相关正文 | 已获授权的功能文档或工作项维护 |
| `docs/project-manager/` | 项目规范建设与维护的工作记录；正式规范正文在 `docs/specs/` 维护 | 按任务需要读取相关记录 | 已获授权的项目规范工作记录维护 |
| `docs/apps-maintenance/` | 公共工程维护的工作记录；工程交付物及长期使用说明在各自明确的长期位置维护 | 按任务需要读取相关记录 | 已获授权的工程维护记录更新 |
| `docs/intake/` | 非权威的候选与草案 | **默认不读** | **默认不写，仅按第 2 章例外进入** |
| `docs/prototypes/` | 非权威的原型与说明 | **默认不读** | **默认不写，仅按第 2 章例外进入** |
| `docs/archive/` | 非权威的历史与失效材料 | **默认不读** | **默认不写，仅按第 2 章例外进入** |

上述权限适用于目录内全部内容。“默认不读”包括不主动浏览、列举、搜索、追踪引用或收集上下文；“默认不写”包括不主动新建、更新、整理或迁入。

检索前限定允许范围，不先全库搜索再过滤。主题相关、资料不足或文件未被 `.ignore` 排除，均不开放这三个目录。引用仅在符合第 2.1 节时允许读取具体 intake 文件，不开放整个目录；其他引用不自动产生访问授权。其他目录也不因可读而自动可写。

## 2. 例外读写授权

对 `docs/intake/`、`docs/prototypes/`、`docs/archive/`，仅在以下任一情况下执行必要读写：

- **具体指令要求**：用户明确指定可确定的文件或事项及操作，例如阅读某份草案、修改某个原型说明、依据指定版本编写新版。
- **已获迁移授权**：负责人已明确授权迁移对象、范围和动作，允许读写完成迁移必需的源材料和目标位置；迁移去向见第 4 章。
- **intake 引用读取**：用户明确要求读取或修改的候选文件直接引用了其他 intake 文件时，可按第 2.1 节读取被引用文件；此例外不包含写入。

授权仅覆盖任务必需的对象和动作：读不包含写，单文件不开放整个目录，编写方案不包含实施。既有有效授权可继续使用，无需重复确认。

被 `.ignore` 排除的内容仍须由用户明确要求访问，迁移授权不自动开放被排除的内容。缺少必要权限时，说明具体对象和原因，只暂停受影响的操作。

### 2.1 intake 候选文件的授权边界

`docs/intake/` 内的文件均为非正式、非权威材料，默认不得读取。读取范围限于用户明确授权的候选文件或可确定的候选范围，以及任务目标候选文件中明确直接引用、与当前任务有关的其他 intake 文件。

- **明确引用允许按需读取**：目标候选文件通过链接、文件路径或可唯一确定的文档名称明确引用其他 intake 文件作为关联资料或依赖时，可以按任务需要读取被引用文件，无需单独请求读取授权。引用读取不改变其非权威属性，也不自动递归开放被引用文件的其他依赖。
- **未引用文件不得自动读取**：未获显式授权、也未被目标候选文件直接引用的其他 intake 文件，不得因同级目录、同一功能、同一事项或补充上下文需要而自动搜索、列举或读取。不得先扫描候选区再筛选相关文件。
- **引用读取不包含写入**：获准修改目标候选文件，可以读取并修改该文件；对引用文件仅有读取权限。确需更新、迁移或清理引用文件时，应说明具体对象和改动范围，取得相应写入授权后再操作；既有有效授权已覆盖的，无需重复确认。
- **范围外资料确有必要时**：说明具体对象、用途及缺失影响，取得明确读取授权后再访问；仅暂停依赖该资料的部分，继续完成已获授权的工作。引用不豁免 `.ignore` 的访问限制。

例如，用户要求修改候选文件 A，A 明确引用了同级候选文件 B：可以读取并修改 A，也可以按需读取 B；修改 B 需要相应写入授权。如果 A 未引用 B，且用户未显式授权读取 B，则不得自动读取 B。A、B 的依据资格均按第 3 章处理。

## 3. 读取后的依据资格

正式目录中的内容须确认已生效、适用于当前任务且未被替代，才能作为依据；目录、标题、版本号和更新时间本身不证明权威性。

候选、原型和归档材料即使获准读取，也只作为本次分析或审核的参考，不直接成为当前规则、功能范围、验收标准或执行授权。与正式依据冲突时，指出分歧，不自行替换正式结论。

获准采用的内容按第 4 章接收到正式维护位置；源材料仍保持非权威属性。同一结论只维护一处正式正文，其他位置使用必要摘要和链接。

## 4. 迁移去向

仅按负责人明确授权的对象、范围和动作迁移。下表规定存放位置，不自动触发迁移。

| 内容 | 接收位置 |
| --- | --- |
| 已获准的功能候选及必要工作材料 | `docs/features/FT-*/` |
| 已获准的项目规范工作材料 | `docs/project-manager/` |
| 已获准的公共工程维护工作材料 | `docs/apps-maintenance/` |
| 正式项目规范正文 | 直接在 `docs/specs/` 创建或更新 |
| 工程长期交付物及使用说明 | 直接在各自明确的长期维护位置创建或更新 |
| 已结束的工作记录、失效材料 | `docs/archive/` 下对应的 `FT-*/`、`project-manager/` 或 `apps-maintenance/` |

- 只接收获准部分，未获准内容留在候选区。
- 工作记录与长期交付物分别维护，不把工作方案整体“转正”为正式正文。
- 确认接收完整，并在允许访问的范围内修复受影响链接；源材料清理、归档或删除按授权范围执行。

完成后简要报告实际改动、内容及链接检查结果和未核验范围。

## 5. 信息权威位置

下表按具体信息规定唯一权威位置，区分任务记录与任务交付物。同一信息的权威正文只在对应位置维护，其他位置仅保留必要摘要和链接；具体内容的依据资格按第 3 章判断。

| 信息 | 唯一权威位置 | 不应重复到 |
| --- | --- | --- |
| 功能级目标、范围和验收标准 | `docs/features/FT-*/spec.md` | 其他功能规格副本 |
| 当前有效的功能设计 | `docs/features/FT-*/desc-*.md` | 其他设计副本 |
| 功能工作记录 | `docs/features/FT-*/WI-*.md` | 功能规格 |
| 项目规范建设与维护任务记录 | `docs/project-manager/WI-*.md` | 正式规范 |
| 工程公共维护任务记录 | `docs/apps-maintenance/WI-*.md` | 被维护的脚本、工具、配置、测试设施或使用说明 |
| 正式项目规范 | `docs/specs/` | 候选材料、WI 或过程记录中的规范副本 |
| 工程公共设施的脚本、工具、配置和测试设施 | 各自明确的代码、脚本、配置或测试目录中的实际交付物 | 工程维护任务记录中的交付物副本 |
| 工程公共设施的长期使用说明 | 该说明明确的长期维护文档 | 工程维护任务记录中的说明副本 |

候选、原型和归档材料不纳入上表，其依据资格仍按第 3 章判断。

信息发生变化时，由获相应授权的维护者更新对应权威正文。工作结束时，应先将已确认且仍有效的长期结论回写到对应权威位置，再归档工作记录；未获所需授权的事项，按第 6.4 节的遗留事项报告要求交接。

## 6. 功能工作结束时的文档收敛检查

检查用于确保长期有效结论有明确的权威正文、文档与实际交付一致、待处理事项可交接。

### 6.1 触发与范围

- AI 执行的功能任务准备提交完成交付结果或收到明确取消决定时，须主动检查本次新增、修改及直接受影响的功能文档和工作记录。其他文档仅按需作为核对依据，不因被引用而纳入收敛范围。
- 负责人确认功能阶段结束，或明确委托全面收敛时，检查对应功能目录中允许访问的材料。
- 普通问答、只读咨询和会话暂停本身不触发检查。已有检查结果且相关内容未变化时可复用，否则补查受影响部分。

### 6.2 检查事项

1. **长期结论**：按第 5 章核对已确认且仍有效的结论是否回写到权威位置，识别仅留在会话、WI 或临时材料中的待回写内容。
2. **有效性**：核对文档与实际交付及已确认范围是否一致，指出冲突、失效或尚未核实的内容。
3. **重复与阶段性材料**：识别重复副本、已结束工作记录和已无继续使用需要的阶段性材料，给出保留、更新、建议归档或待确认的结论，保留仍有效的权威正文及活跃工作记录。
4. **引用**：核对受影响链接及权威正文入口是否可用，确认拟议归档不会使仍需使用的长期结论只剩归档入口。

阶段结束或受委托全面收敛时，另评估长期文档的持续价值、相对当前实现的必要信息、更新触发条件及维护安排；需负责人决定的保留取舍列为待确认，不在每次小任务结束时重复评估。

### 6.3 处理边界

访问、依据资格和处理遵守第 1～5 章及项目协作规则。检查不产生额外授权，不替代验收或自动改变 WI 状态；涉及 WI 验收或状态维护时，遵守[WI工作项维护规范](./WI工作项维护规范.md)。

### 6.4 完成与报告

检查范围内各项已有结论，无法核验的部分已说明对象、影响及所需条件，即可报告检查完成；仍有待处理或未核验事项时，不得宣称收敛处理已全部完成。

结果随本次交付在对话中报告：简述检查范围、结论及实际处理与验证结果；有遗留事项时，列明文件或缺失结论、建议动作与目标位置、所需授权或待负责人决定事项，便于接续。无相关文档且无待保留结论时，简要说明无待收敛内容。

已获工作记录维护授权时，将必要交接信息写入对应记录，不为检查另建文档、WI 或重复台账。
