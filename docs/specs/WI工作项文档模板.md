# WI工作项文档模板

## 1. 适用范围与使用说明

本文提供与《WI工作项维护规范》配套的统一文档结构、填写提示和示例，供创建、补齐和检查 WI 时参考。本模板不另行定义规则，也不构成执行授权。

[WI工作项维护规范](./WI工作项维护规范.md)为已生效的规范正文。WI 定义、字段与填写规则、准入、状态及委托验收要求均由规范正文定义；本文仅呈现对应结构和提示，不另行定义规则。存放、迁移与归档遵循项目已生效的目录约定。

### 1.1 模板使用说明

复制第 2 节模板，替换适用的 `<占位符>`，按实际数量增补交付物和完成标准。第 3 节用于选择填写角度，第 4～5 节提供任务示例，第 6 节展示“当前下一步”的填写方式；普通执行按维护规范和当前 WI 推进，无须加载这些示例。

### 1.2 示例使用说明

本文示例中的人员、路径、环境、审核及委托事实均为虚构，不声明路径实际存在，也不构成实际任务或授权。使用时须替换为经核实的资料和实际准入、委托及维护依据；局部示例未展示的内容仍须按统一模板补齐。

## 2. 统一 WI 模板

```markdown
# WI-<编号>：<任务名称>

- status: <ready / in_progress / blocked / done / cancelled>
- priority: <P0 / P1 / P2 / P3>
- owner: <唯一负责人>
- created: <YYYY-MM-DD>
- updated: <YYYY-MM-DD>
- due: -
- review_on: -
- blocked_by: -

## 目标

<用一句话说明完成后获得的能力、结果或结论。>

## 交付物

- D1：<产物名称、存放位置或交付形式>

## 完成标准

- [ ] AC1：<可观察、可判断的通过条件>
  - 对应交付物：<D1>
  - 验证方式：<测试、检查、演示或评审方式>
  - 所需证据：<应提交的记录或结果>

## 关联资料与启动条件

- 关联资料：<实际路径或链接；由拆分或终态后续工作建立时引用原 WI；已确认没有则填写“无”>
- 启动依赖：<资料、环境、权限或前置结论；没有则填写“无”>
- 依赖核实：<核实结果及日期；无依赖则填写“不适用”>

## 执行边界

- 允许读取：<资料及文件范围>
- 允许修改：<产物类型及文件、目录或模块范围；只读任务填“无”>
- 允许执行的验证：<环境、验证动作及必要限制>
- 不包含：<明确排除的工作>
- 暂停条件：<需要负责人决定或补充授权的具体情形>

## 准入与委托

- 准入审核：<审核人、日期、结论>
- 执行委托：<未委托 / 已委托 / 已失效；已委托注明当前执行者，失效注明原因、日期及依据>
- 委托依据：<实际委托来源、日期、适用 WI 及授权范围；未委托填“不适用”；失效或重新委托保留必要的前次记录>
- WI 维护：<维护责任人；AI 维护时注明实际授权依据、日期、适用 WI 及范围>

## 当前下一步

- 动作：<当前应推进的一个工作节点；done 或 cancelled 可填“无”>
- 执行方：<AI / 负责人 / 其他明确责任方；无动作填“不适用”>
- 完成判据：<何时视为该节点完成；无动作填“不适用”>

## 阻塞信息

- 阻塞前是否已开始：<是 / 否；未阻塞填“不适用”>
- 待满足条件：<解除阻塞所需的事实或决定；未阻塞填“不适用”>
- 解除或复查动作：<引用当前下一步，必要时补充处理方；未阻塞填“不适用”>

## 关键记录

<按维护规范记录影响范围、判断或交接的事实及日期、依据，包括状态转换、范围调整批准及前后摘要、拆分决定与后续去向、阻塞复查或误记更正；授权事实引用“准入与委托”；暂无则填写“无”。>

## 结果与验收

- 实际交付：<待产出 / 已交付内容及位置>
- 验证结果与证据：<按 AC 编号逐项记录结果及证据位置；未验证明确填写>
- 遗留问题：<尚未核实 / 无 / 具体问题及影响>
- 验收：<待验收 / 验收人、日期、明确结论及依据；未通过时注明未通过项、反馈及待补充证据；取消且未验收填“不适用”>
- 取消原因：<原因；未取消填“不适用”>
- 取消决定：<决定人、日期及依据；未取消填“不适用”>
```

## 3. 不同工作性质的填写指引

工作性质通过目标、交付物和完成标准表达，并不设置分类字段。实现、修复、维护、调研、决策、文档修订、试点与评估属于工作性质，是非穷尽的示例，不作为 WI 的准入限制。
下表提供不同工作性质的填写参考，不用于增加分类字段或判断准入；适用范围、准入和拆分要求以维护规范为准。

| 工作性质 | 目标关注点 | 交付物关注点 | 完成标准关注点 |
| --- | --- | --- | --- |
| 实现 | 完成后具备的行为或能力 | 实现产物及对应验证记录 | 预期行为、边界条件及验证证据 |
| 修复 | 消除的具体问题及复现条件 | 修复产物及复现、回归验证记录 | 原问题不再出现，相关既有行为符合预期 |
| 维护 | 维护对象及可观察的改善结果 | 更新后的文档、工具或其他可验证产物 | 改善结果成立，不能仅填写“完成维护” |
| 调研 | 明确的研究问题和调查边界 | 有来源依据的调查结果、结论及不确定项 | 覆盖约定问题，证据可核查，明确局限和未解决事项 |
| 决策 | 待决定事项及比较标准 | 选项比较、建议及负责人确认的结论 | 依据完整、差异明确，所需决定由负责人确认 |
| 文档修订 | 文档要表达的规则或信息及适用范围 | 修订后的指定文档 | 内容准确一致、引用有效，并满足约定评审要求 |
| 试点与评估 | 待验证的改进效果及试点范围 | 试行记录、效果评估及后续建议 | 按约定周期、指标和证据评估，明确是否达到预期及评估局限 |

调研 WI 可以将调查、实验、比较及建议整理列为交付内容，说明研究问题、调查范围和证据形式，无须预填结论。决策 WI 可以围绕选项比较和建议填写 AI 的交付物，单独写明需负责人确认的选择及其验收依据。

维护 WI 可以围绕一份可验证的指南或工具描述结果；第 4 节以补齐并验证本地启动指南为例。

## 4. 工程公共维护完整示例

以下为已准入、尚未委托的完整示例，文件名为 `WI-01-补齐本地启动指南.md`。

```markdown
# WI-01：补齐本地启动指南

- status: ready
- priority: P2
- owner: @项目负责人
- created: 2026-09-10
- updated: 2026-09-10
- due: -
- review_on: -
- blocked_by: -

## 目标

首次接触项目的开发者能够按照指南启动本地服务。

## 交付物

- D1：更新后的本地启动指南，保留在 docs/guides/local-start.md。
- D2：本 WI“结果与验收”中的指南核对结果及启动验证记录。

## 完成标准

- [ ] AC1：指南完整说明所需环境、配置项和启动命令，且与现有启动配置一致。
  - 对应交付物：D1
  - 验证方式：对照 package.json、.env.example 和 scripts/dev.sh 逐项检查指南。
  - 所需证据：环境要求、配置项及启动命令的核对结果，注明检查文件及版本。
- [ ] AC2：在已授权的本地环境中，仅按更新后的指南完成一次启动并确认服务可用。
  - 对应交付物：D1、D2
  - 验证方式：在现有依赖和本地配置齐备的隔离环境执行指南命令，检查启动输出及本地健康检查响应。
  - 所需证据：验证日期、系统和运行时版本、代码版本、执行命令、启动结果及健康检查结果，不记录凭据。
- [ ] AC3：验证记录逐项覆盖 AC1、AC2，并明确无法验证的内容及遗留问题。
  - 对应交付物：D2
  - 验证方式：检查每项标准是否有结果和证据，核对失败或未验证事项是否如实记录。
  - 所需证据：本 WI“结果与验收”中的逐项记录。

## 关联资料与启动条件

- 关联资料：docs/guides/local-start.md、package.json、.env.example、scripts/dev.sh。
- 启动依赖：现有指南和参考文件可访问；本地隔离环境已有所需依赖和配置，启动不需要安装依赖、数据库迁移或业务数据修改。
- 依赖核实：@项目负责人于 2026-09-10 确认上述资料及环境已具备，允许在委托后按下述范围开展验证。

## 执行边界

- 允许读取：上述关联资料及本 WI；遵守项目默认访问规则，不读取实际凭据文件。
- 允许修改：文档产物 docs/guides/local-start.md；本 WI 的维护责任和授权另见“准入与委托”。
- 允许执行的验证：在已准备的本地隔离环境运行 scripts/dev.sh，检查本地健康检查响应并停止本次启动的进程；仅允许必要的临时运行文件和日志，不连接生产或其他外部服务。
- 不包含：修改代码、依赖、启动脚本、工程配置和实际环境配置，执行数据库迁移或业务数据修改。
- 暂停条件：必须修改上述排除产物、增加访问权限、连接外部服务，或无法按限定环境提供启动成功证据。

## 准入与委托

- 准入审核：@项目负责人 / 2026-09-10，确认目标、交付物、完成标准、依赖及执行边界，同意建立正式 WI，优先级为 P2。
- 执行委托：未委托。
- 委托依据：不适用。
- WI 维护：@项目负责人；尚未授予 AI 维护权限。

## 当前下一步

- 动作：委托后，对照现有启动配置核对指南，明确环境、配置项及命令的缺漏。
- 执行方：待委托的 AI 执行者。
- 完成判据：形成 AC1 对应的逐项核对结果，明确需补充的内容以及是否存在超出执行边界的问题。

## 阻塞信息

- 阻塞前是否已开始：不适用。
- 待满足条件：不适用。
- 解除或复查动作：不适用。

## 关键记录

无。

## 结果与验收

- 实际交付：待产出。
- 验证结果与证据：AC1、AC2、AC3 均未验证。
- 遗留问题：尚未核实。
- 验收：待验收。
- 取消原因：不适用。
- 取消决定：不适用。
```

## 5. 项目管理机制改进填写示例

项目管理机制改进可以先识别问题调研、机制决策、文档修订、工具实现和试点评估之间的结果依赖，再按维护规范的粒度规则确定 WI 边界。例如，尚需调研才能决定机制时，先定义调研 WI，实施范围待前置结论确认后再审核。改进方向已确认、规范与模板共同交付同一套规则且可一并验收时，可按下例填写一个 WI。

以下为“修订 WI 准入检查规则及配套模板”的局部填写示例，仅展示目标、交付物、完成标准、执行边界和当前下一步。假定负责人已确认改进方向：准入检查须覆盖目标、交付物、完成标准、启动依赖和执行边界，并在模板中提供对应填写位置。

```markdown
## 目标

负责人能够依据一致的规则和模板，检查 WI 是否满足正式准入条件。

## 交付物

- D1：修订后的准入检查规则文档 docs/process/wi-rules.md。
- D2：与规则一致的配套模板 docs/process/wi-template.md。

## 完成标准

- [ ] AC1：规则明确目标、交付物、完成标准、启动依赖和执行边界的准入检查要求及负责人确认责任。
  - 对应交付物：D1
  - 验证方式：对照负责人已确认的改进方向，逐项审阅规则。
  - 所需证据：各检查项对应的文档位置及审阅结果。
- [ ] AC2：模板为上述检查项提供对应填写位置，字段及提示与规则一致，两份文档之间的相对链接及章节引用有效。
  - 对应交付物：D1、D2
  - 验证方式：逐项核对规则与模板，检查链接目标文件及章节。
  - 所需证据：规则与模板的对应核对结果及链接检查结果。
- [ ] AC3：负责人评审通过两份文档，确认其符合已确定的改进方向。
  - 对应交付物：D1、D2
  - 验证方式：提交文档及 AC1、AC2 证据供负责人评审，按确认意见完成必要修订。
  - 所需证据：针对文档版本的明确评审通过结论、评审人及日期。

## 执行边界

- 允许读取：负责人已确认的改进要求、docs/process/wi-rules.md、docs/process/wi-template.md 及本 WI；遵守项目访问边界。
- 允许修改：文档产物 docs/process/wi-rules.md 和 docs/process/wi-template.md；本 WI 的维护责任和授权另见“准入与委托”。
- 允许执行的验证：文档内容核对、相对链接及章节引用检查，不运行工程代码。
- 不包含：工具实现、配置修改、自动化实现、批量更新现有 WI 或发布新机制。
- 暂停条件：需改变已确认的改进方向、修改指定文档以外的产物，或涉及工具、配置、自动化实现时，先由负责人明确范围及授权。

## 当前下一步

- 动作：委托后，对照已确认的改进要求核对规则与模板，确定需要补齐或修订的位置。
- 执行方：待委托的 AI 执行者。
- 完成判据：五项准入检查要求均有对应位置或明确缺漏，且已识别是否存在超出执行边界的问题。
```

## 6. 当前下一步填写示例

以下局部示例假定接口实现已获委托，AC1～AC3 已明确超时和模型错误的映射要求及验证方式。状态及节点更新以维护规范为准。

| 场景 | 动作 | 执行方 | 完成判据 |
| --- | --- | --- | --- |
| 实现与验证 | 补齐超时和模型错误映射，并通过对应测试 | 已获委托的 AI 执行者 | AC1～AC3 对应测试通过，验证证据已记录 |
| 正常等待验收 | 依据 AC1～AC3 验收接口实现及验证证据 | 负责人 | 给出针对该 WI 的明确验收结论 |
| 错误语义需要调整，且当前授权内已无其他可推进动作 | 确认错误语义调整方案及后续执行范围 | 负责人 | 明确采用的语义、是否调整完成标准及授权范围 |

第一行覆盖同一节点内的多次读取、修改、测试和修复，无须展开工具调用清单。第二行对应 `in_progress`。第三行对应 `blocked`，还需在元信息填写阻塞原因与复查日期，并补齐“阻塞信息”；如仍有可推进动作，则保持 `in_progress`，将当前动作写入下一步，在关键记录中说明局部障碍。
